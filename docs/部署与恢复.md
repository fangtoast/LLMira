# 部署与恢复

本文面向单组织自托管管理员，覆盖 Docker Compose 首发拓扑。生产签名、域名、证书和商店账号由发布方提供。

## 上线前

1. 从 `.env.example` 生成部署环境变量，不要复用开发默认值。
2. 为 `JWT_SECRET` 和 `ENCRYPTION_MASTER_KEY` 生成独立高熵随机值。
3. 设置数据库和 MinIO 强密码；把部署变量放进主机密钥管理，不提交仓库。
4. 将 `LLMIRA_SITE_ADDRESS` 设置为正式域名，启用 `COOKIE_SECURE=true`。
5. 限制 4000、5432、6379、9000 仅容器网络可见，对外只开放 80/443。

## 启动与检查

```powershell
docker compose up -d
docker compose ps
```

检查 Web 首页和 `/api/v1/health`，再完成管理员初始化。启用 OCR 或运维备份：

```powershell
docker compose --profile ocr up -d
docker compose --profile ops up -d
```

## 备份

`ops` profile 每日生成 PostgreSQL 备份，并把 MinIO `llmira` bucket 镜像到主机 `backups/`。生产环境还应：

- 把备份复制到不同故障域并加密；
- 至少保留 14 个日备份和月度归档；
- 对数据库、对象存储和 `ENCRYPTION_MASTER_KEY` 使用同一恢复版本；
- 监控备份退出码、文件大小和最近成功时间。

## 恢复演练

恢复必须在隔离环境中执行：

1. 新建空 PostgreSQL 与 MinIO；
2. 恢复数据库备份和对应对象快照；
3. 使用原主加密密钥启动 API/Worker；
4. 验证登录、工作区列表、至少一份知识文档、引用、Provider 可用性和审计；
5. 记录 RPO/RTO、缺失对象和校验结果；
6. 演练环境验证后销毁，不把测试 Cookie 或密钥带回生产。

建议每月至少演练一次。仅“生成了备份文件”不等于恢复已验证。

## 升级

升级前先备份。数据库迁移是追加式文件；先在恢复演练副本执行，再更新 API、Worker 和静态客户端。共享嵌入模型变化需要显式重建全部知识索引。
